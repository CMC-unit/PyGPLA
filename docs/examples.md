# Examples

This page collects short, runnable examples. For a fuller walkthrough see the
{doc}`quickstart` and {doc}`tutorials` pages.

## Basic GPLA on simulated data

Simulate transiently coupled spikes and an analytic LFP, then run GPLA through
the high-level API:

```python
import numpy as np

from pygpla.api import gpla
from pygpla.simulations import simulate_transient_locked

rng = np.random.default_rng(123)

signal_params = dict(nCh=1, nUnit=12, SF=600.0, nTr=6, signalLength=6.0)
global_params = dict(
    oscFreq=20.0,
    nCycl=15,
    syncSigProportion=0.7,
    lfpPhaseNoise_kappa=8.0,
    whiteNoise_sigma=0.05,
)
spike_params = dict(avefiringRate=18.0)
coupling_params = dict(lockingStrength_kappa=10.0, lockingPhase=0.0)

lfp_real, lfp_analytic, spikes, meta = simulate_transient_locked(
    global_params,
    spike_params,
    coupling_params,
    signal_params,
    return_analytic=True,
    rng=rng,
)

result = gpla(
    spikes,
    lfp_analytic,                 # (channels, samples, trials), complex dtype
    stats_config=None,
    plvNrmlzMethed="var1_theoretical",
    flag_whitening=0,
    flag_lfpNrmlz=0,
)

print("gPLV:", result.gplv)
print("LFP vector shape:", result.lfp_vector.shape)
print("Spike vector shape:", result.spike_vector.shape)
```

## Choosing a statistical test

GPLV significance can be assessed with spike-jitter surrogates or analytically
(Random Matrix Theory). Pass a `stats_config` dict to select the test.

Spike-jitter surrogate test (group-preserved interval jittering):

```python
stats_config = {
    "testType": "spike-jittering",
    "jitterType": "group-preserved-interval-jittering",
    "nJtr": 50,
    "alphaValue": 0.05,
    "spkSF": signal_params["SF"],
    "jitterWinWidth": 1.0 / global_params["oscFreq"],
}
result_jitter = gpla(spikes, lfp_analytic, stats_config=stats_config)
print("Jitter p-value:", result_jitter.p_value)
```

The analytical Marchenko–Pastur (RMT) test (`{"testType": "RMT-based"}`) is also
available and avoids surrogate generation. It is defined for the variance-unit
normalization (`plvNrmlzMethed="var1_theoretical"`) and typically paired with
whitening; see {doc}`api` for the full set of `stats_config` options. Because it is
a threshold test, it returns a reject/accept **decision** rather than a p-value, so
`result.p_value` is `NaN` for it by design — read
`result.stats["gPLV_stats"]["nullHypoReject"]` instead.
